# BDC Extensible Enumeration Value Does Not Match the Investment Identifier Key Value Pair
Rule ID: DQC.US.0259.10984  
Status: Proposed  
Public Review Release date: TBD  
Effective date: TBD

## Rule Function

**Purpose:**

The purpose of Rule DQC.US.0259 is to ensure that when a Business Development Company (BDC) identifies the attributes of an investment both with an extensible enumeration element and with a key value pair (KVP) on the `InvestmentIdentifierAxis`, the two are consistent.

**Conditions:**

Assertion 10984 fires when all of the following are true:

1. The filing is a BDC filing (`$BDC_FLAG`).
2. A fact is reported for one of the following extensible enumeration elements with a member on the `InvestmentIdentifierAxis`.
3. The `InvestmentIdentifierAxis` member uses the KVP format (`SecurityName|KEY1=value1 KEY2=value2`).
4. The KVP string includes the key related to the extensible enumeration element (see the table below).
5. The value of that key does not match the member name (local name) of any qname in the value of the extensible enumeration fact.

| Extensible Enumeration Element | Related KVP Key |
|---|---|
| `InvestmentIssuerAffiliationExtensibleEnumeration` | `AFF` |
| `InvestmentIssuerGeographicRegionExtensibleEnumeration` | `GEO` |
| `InvestmentIndustrySectorExtensibleEnumeration` | `IND` |
| `InvestmentIssuerNameExtensibleEnumeration` | `ISS` |
| `InvestmentTypeExtensibleEnumeration` | `TYP` |

If the `InvestmentIdentifierAxis` member does not use the KVP format, or the KVP string does not include the related key, the rule does not run for that fact. Missing required keys are reported by DQC.US.0246.

## Problem Solved by the Rule

BDCs can identify the issuer, affiliation, geographic region, industry sector and investment type of each investment on the Schedule of Investments in two ways:

1. By reporting the extensible enumeration elements listed above for each member of the `InvestmentIdentifierAxis`.
2. By including the same attributes as keys in the KVP string of the `InvestmentIdentifierAxis` member, as validated by DQC.US.0246.

When a filer uses both methods, the extensible enumeration value and the KVP value should describe the same attribute. If they differ, users cannot determine which value is correct. For example, an investment could be reported with `InvestmentTypeExtensibleEnumeration` = `FirstLienSeniorSecuredMember` while its KVP identifies the type as `TYP=SecondLienMember`.

## Example Rule Message

The fact with concept name us-gaap:InvestmentTypeExtensibleEnumeration and a value of set(DelayedDrawTermLoanMember) is an extensible enumeration and has no corresponding Key Value Pair (KVP) in the InvestmentIdentifierAxis. The value of the extensible enumeration fact should be a value specified in the KVP.

The InvestmentIdentifierAxis member ABC Holdings Corp, Delayed Draw Term Loan|TYP=TermLoanMember ISS=ABCHoldingsCorpMember reports the key TYP with a value of TermLoanMember. This does not match the value of the extensible enumeration fact set(DelayedDrawTermLoanMember). Please ensure the extensible enumeration value and the KVP value for the key TYP identify the same item.

## Technical Details

- KVP members are identified using the function `is_kvp_member`, which returns true when the typed member contains both `|` and `=`.
- The KVP value for each key is extracted using the function `get_dim_key_value`. The element-to-key mapping is defined in the constant `$ENUM_KVP_KEYS`.
- The value of an extensible enumeration fact is a set of qnames. The rule compares the KVP value with the local name of each qname, so the KVP must use the member name. Alias labels are not accepted.
- The rule only evaluates extensible enumeration facts reported with the `InvestmentIdentifierAxis`.
- The rule is complementary to DQC.US.0246, which validates the format, keys and values of the KVP string, and DQC.US.0208, which checks that extensible enumeration and KVP values are used as members on the `InvestmentTypeAxis` and `EquitySecuritiesByIndustryAxis`.

The rule exists in the 2026 US GAAP taxonomy version.
